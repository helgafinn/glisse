Left edge

Brightness, on the real backlight

Not a dark overlay and not a gamma trick. The panel is actually dimmer, and the display you see is the one macOS draws itself rather than a lookalike.

Right edge

Volume, following your output

The trackpad ticks under your finger as the value moves, driven by the actuator so it works from a background app. Headphones, speakers, whatever is current.

The activation rule

A drag only counts if it starts on the edge.

Being near an edge is not enough. The gesture has to begin inside the edge strip, and it has to be the only finger on the trackpad. A touch that starts in the middle and later wanders to the edge can never activate the slider, for its whole life.

It also stops listening for half a second after every keystroke, so typing never sets it off. Unglamorous rules, and most of the reason it feels like part of the system. This page behaves the same way — dragging from the middle does nothing.

Everything it does

Twelve small
decisions.

  • Edge slidingLeft for brightness, right for volume. The sides are swappable.
  • The real system HUDThe display macOS draws, never an imitation of it.
  • Haptic ticksOff, light, medium or strong, on value progress.
  • Pause while typingFor half a second after each keystroke, gestures are refused.
  • Fine controlThe same gesture, with a much smaller change.
  • Bottom quarter onlyRestrict where a gesture may start, if you catch it by accident.
  • Modifier requirementHold or toggle Control, Option, Command, Shift or Fn.
  • Freeze the pointerThe cursor stays exactly where it was while you slide.
  • Three-finger middle clickDeliberate taps only; swipes are left to macOS.
  • External monitorsBrightness over DDC, writing VCP 0x10 with a capability probe.
  • Launch at loginRegistered properly through SMAppService.
  • Menu bar onlyOne small glyph. No dock icon, no window.
Install

Free, and open
from top to bottom.

brew install --cask --no-quarantine helgafinn/tap/glisse

Or take the DMG from the releases page. MIT licensed. No trial, no licence key, no account, no telemetry, no analytics, and no network code of any kind — the app makes no outbound connection, ever.

The main feature needs no permission at all. Sliding, volume and brightness work the first time you launch it, before you have granted anything. Accessibility is asked for only to draw the system HUD and for three optional extras, and both event taps it installs are listen‑only, so they cannot swallow or alter a keystroke.

The honest part

What is not
finished yet.

  • Ad-hoc signed, not notarisedNotarising needs a paid Apple Developer account this project does not have. That is what --no-quarantine is for, and it costs something real: macOS forgets the Accessibility permission on every upgrade, so you grant it again.
  • No App Store version, and there cannot be oneReading raw trackpad contacts, drawing the system HUD and talking to a monitor over I2C have no entitlements available. This is a program you choose to trust, and it should say so rather than implying a review vouched for it.
  • External monitor brightness is unverifiedThe DDC path is written and the reply parser follows the spec, but no second display was available to test it on.
  • Intel and Magic Trackpad are unverifiedThose code paths exist and compile. Nobody has run them on that hardware yet.

Every private system call is listed in the README with the reason no public alternative exists. If you want the reasoning rather than the app, the write-up on the missing brightness API is the long version.
